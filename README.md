## Введение

REST API является фундаментальным компонентом современных распределённых систем, обеспечивая взаимодействие между сервисами, клиентскими приложениями и внешними интеграциями. Производительность API напрямую влияет на пользовательский опыт, масштабируемость системы и её способность выдерживать реальные нагрузки. Поэтому тестирование производительности REST API является обязательным этапом обеспечения качества.

---

# 1. Виды тестирования производительности REST API

## 1.1. Нагрузочное тестирование

Нагрузочное тестирование (Load Testing) — это проверка работы API при нагрузке, которая считается нормальной или близкой к ожидаемой в реальной эксплуатации. Его задача — убедиться, что система стабильно работает в пределах проектных значений.

### Что обычно проверяют

- стабильность времени отклика при росте числа запросов;
- способность API выдерживать длительную нагрузку без деградации;
- корректность работы под типичным трафиком (например, 500 RPS в течение часа);
- соответствие SLA, если оно определено.

### Типичные проблемы

- постепенное увеличение времени отклика;
- утечки памяти;
- рост очередей в базе данных;
- неэффективные запросы, проявляющиеся только под нагрузкой.

### Пример

> API интернет-магазина должен выдерживать 2000 запросов в минуту в течение рабочего дня.  
> Нагрузочный тест имитирует такой трафик, чтобы убедиться, что система не теряет производительность к концу дня.

---

## 1.2. Стрессовое тестирование

Стрессовое тестирование (Stress Testing) направлено на определение предельных возможностей системы. В отличие от нагрузочного тестирования, здесь нагрузка намеренно превышает нормальные значения.

### Цели стресс-тестирования

- определить точку отказа API;
- понять поведение системы при перегрузке;
- проверить способность к восстановлению после отказа;
- выявить узкие места, не проявляющиеся при обычной нагрузке.

### Что важно учитывать

- анализировать не только момент отказа, но и поведение после него;
- проверять корректность обработки ошибок (например, возврат 503 вместо зависания);
- оценивать способность API восстановиться без ручного вмешательства.

### Пример

> Если API рассчитан на 1000 RPS, стресс-тест может довести нагрузку до 5000 RPS,  
> чтобы определить момент деградации и скорость восстановления.

---

## 1.3. Объёмное тестирование

Объёмное тестирование (Volume Testing) проверяет работу API при больших объёмах данных.

### Что проверяют

- время обработки больших payload;
- влияние размера данных на время отклика;
- устойчивость к большим JSON-ответам;
- корректность работы при больших объёмах данных в базе.

### Типичные проблемы

- переполнение памяти при сериализации больших объектов;
- медленные запросы к базе данных;
- увеличение времени сборки мусора (GC);
- ошибки при обработке крупных файлов.

### Пример

> API аналитической системы должен возвращать отчёты размером до 20 МБ.  
> Объёмный тест проверяет, не приводит ли это к перегрузке сервера.

# 2. Метрики производительности REST API

## 2.1. Время отклика (Response Time)

Показывает, сколько времени проходит между отправкой запроса и получением ответа.

### Варианты измерений

- среднее время отклика;
- медиана;
- 95-й и 99-й перцентили;
- максимальное время отклика.

---

## 2.2. Пропускная способность (Throughput)

Количество запросов, которое API способен обработать за единицу времени (обычно RPS).

### Что важно

- стабильность пропускной способности при росте нагрузки;
- зависимость RPS от размера данных;
- способность API сохранять производительность при длительных нагрузках.

---

## 2.3. Уровень ошибок (Error Rate)

Процент запросов, завершившихся ошибкой (4xx, 5xx).

### Что анализируют

- рост ошибок при увеличении нагрузки;
- типы ошибок;
- связь ошибок с временем отклика.

---

## 2.4. Использование ресурсов (CPU / Memory / Disk / Network)

Мониторинг ресурсов является обязательной частью нагрузочных тестов.

---

## 2.5. Latency (задержка)

Время, которое запрос проводит в очереди до начала обработки.

---

## 2.6. Concurrency (число одновременных соединений)

Показывает, сколько клиентов API может обслуживать одновременно без деградации.

---

# Заключение

Тестирование производительности REST API является важной частью обеспечения качества современных систем. Нагрузочные тесты позволяют убедиться, что система выдерживает ожидаемый трафик. Стрессовые тесты помогают определить пределы и подготовиться к пиковым ситуациям. Объёмные тесты выявляют проблемы, связанные с большими данными.

Использование метрик — от времени отклика до уровня ошибок и загрузки ресурсов — позволяет принимать инженерные решения на основе объективных данных и поддерживать стабильность системы.
